# Screen-builder contract (read fully before writing a screen module)

You are building one or more artboards for the ScopeWise complete-app design canvas. Every
artboard is generated by Python from `dc.py` and rendered by the Design Components runtime.
The owner's rules: **darker text, one typeface (IBM Plex Sans), colour only where it carries
meaning, polished, and nothing from the live app missing.** The inventories under `inventory/`
are the verbatim source of truth for labels, controls, states and behaviours. If it is in the
inventory for your screen, it must be on your artboard with the same wording.

## Files you create

- `screens/<route>.py` — one module per screen (see `screens/codereview_list.py` as the model).
  Exports: `STEM` (PascalCase artboard stem), `DATA` (sample data, JSON-serialisable), `BODY`
  (markup), `VALS` (JS body of `renderVals`, see below), `CLICKS` (harness steps), and
  `build(phone=False) -> [(stem, html)]` which calls `screen(...)`.
- `labels/<Stem>.json` — a JSON list of every verbatim string from the inventory for that screen
  (headings, buttons, placeholders, aria-labels, tooltips, empty/error/status copy, select
  options, table headers). The completeness check asserts each appears in the artboard.
- Do NOT edit `dc.py`, `logic.js`, `gen.py`, `harness.py`, `check_labels.py`, `labels.json`,
  or other screens' modules. If a primitive is missing, build it locally in your module with
  the same CSS classes; note it in your report so it can be promoted.

## The format in one page

- Markup is HTML with DC holes: `{{path}}` is a dotted lookup only (no expressions, no
  ternaries). Precompute every string, colour, class and boolean in `VALS`.
- Loops: `<sc-for list="{{rows}}" as="r" hint-placeholder-count="3"> … {{r.x}} … </sc-for>`.
- Branches: `<sc-if value="{{cond}}" hint-placeholder-val="{{true}}">…</sc-if>` (always set the
  hint attribute).
- Events: JSX names as whole-value attrs: `onClick="{{r.open}}"`, `onChange="{{setQ}}"`,
  `onKeyDown="{{key}}"`, `onPointerDown`… The value must be a function from `VALS`.
- Inputs: `value="{{x}}"` + `onChange` (text/select/checkbox `checked="{{x}}"`); ranges add
  `onInput`. A hole inside an element renders as **text** (never HTML): swap icons or markup
  with two `<sc-if>` branches, not with a hole.
- Attribute interpolation: `class="tab {{t.a.cls}}"`, `style="width:{{w}}"` are fine.
- `[[name]]` is the Python-side template token (filled by `T()`); never use f-strings on markup.
- Never emit `<iframe>`; never attach document/window key listeners.

## Primitives (from `dc.py`) and their state contracts (`logic.js` methods on `self`)

| Helper | Markup it emits | Runtime values it expects in `VALS` |
|---|---|---|
| `app_shell(active, body, wide=False)` | sidebar + mobile nav + `.page` | provided automatically (`shell`, `is`, `req`, `root`, `stop`, `ready`) |
| `tabs("t", [(key,label)…])` + `panel("t", key, inner)` | tablist + `<sc-if>` panels | `t: self.tabVals('t', ['k1','k2'])` |
| `sheet("name", head, body, foot, aria)` | resizable right sheet | `sheets: { name: self.sheetVals('name', 448) }`; open with `self.openSheet('name', id, 448)` |
| `dialog("name", title, body, actions, width)` | modal | `dlg: { name: self.dlgVals('name') }`; open with `self.openDlg('name', arg)`; close via `{{dlg.name.close}}` |
| `kebab("r.menu", [(label, "{{r.handler}}", cls, icon)…], aria)` | per-row menu | each row: `menu: self.menuVals(rowId)`; menus close on root click |
| `th("tbl", "key", "Label", align, tip)` | sortable header | `tbl: self.sortVals('tbl', rows, [{key:'name'}, {key:'score'}, {key:'x', get:r=>…}], 'name', 'asc')` → `{{tbl.rows}}` + `{{tbl.h.key.*}}` |
| `dropzone("dz", label, hint, aria)` + `filerow("dz", "dz.removeAria")` | dropzone + selected file row | `drop: { dz: Object.assign(self.dropVals('dz', 'sample.xlsx', '0.4 MB'), {removeAria:'Remove sample.xlsx'}) }` |
| `states(default, loading, empty, error, gated)` | the five `view` states | automatic (`is.*` from the `view` tweak) |
| `btn`, `chip`, `dot_chip`, `kpi`, `alert`, `skel`, `icon`, `request_access_form` | static markup | none, except `request_access_form()` uses the automatic `req` values |
| inline rename | `self.renameVals(id, current, onCommit)` → `{on, off, value, start, set, commit, cancel, key, canSave}` | pattern: `<sc-if value="{{r.rn.off}}">…title…</sc-if><sc-if value="{{r.rn.on}}"><input value="{{r.rn.value}}" onChange="{{r.rn.set}}" onKeyDown="{{r.rn.key}}"></sc-if>` |
| listbox | `self.lbVals('runs')` → `{open, cls, aria, toggle}` | build the popover with `class="menu {{lb.cls}}"` |
| busy labels | `self.busy('k')`, `self.runBusy('k', ms, after)` | e.g. `label: self.busy('test') ? 'Testing…' : 'Test'` |
| expanders | `self.isOpen(id)`, `self.toggleOpen(id)` | |
| state | `self.setIn(['path','to','key'], value)`; `self.state` is JSON-only (no functions) | initial state passed as the `state` argument of `screen()` (deep-merged over `BASE_STATE`) |

`VALS` is the body of a function `(self) => { const S = self.state, D = self.data(); … return {…}; }`
— `S`, `D`, `P` (props) are in scope; return an object; it is merged over the automatic values.

Tweaks: `screen(..., props={...})` may add `"density": {"editor":"enum","options":["comfortable","compact"],"default":"comfortable"}`.
Read them as `P.density`. Keep tweaks to `view`, `density`, `admin` — no copy as tweaks.

Phone: same file, media query at 760px. Grids `.g2/.g3` become one column, `.g4+` two. Tables:
add class `tbl cards` and `data-th="Header"` on every `<td>` so rows become cards. Put
`white-space:nowrap` only on chips and numbers. Every clickable control ≥ 30px tall; 44px on
phone where it is a primary action.

Tooltips: `class="tip" data-tip="…"` on any chip, KPI, icon button or truncated cell — use the
exact tooltip text from the inventory.

## Definition of done for a module

1. `python gen.py --only <Stem>` writes `<Stem>.dc.html` and `<Stem>Phone.dc.html`. gen.py
   auto-discovers every `screens/*.py` that exports `STEM` and `build`; also export `PAGE`
   (`system|sow|mitre|code|admin`), `TITLE` and `ORDER` (int) so the canvas lays it out.
2. `python check_labels.py` passes for your stems (the check reads `labels.json`; for your
   screen put the list in `labels/<Stem>.json`; the maintainer merges).
3. `python harness.py --screens <Stem> --out <scratch>` and `--phone` both **PASS**
   (mounted, no `{{` leak, no console errors after ready, no horizontal overflow, every
   CLICKS step ok). Environment: `PYTHONUTF8=1`, `DC_RUNTIME=<folder with reactUmd.js,
   reactDomUmd.js, supportJs.js>` (given in your task).
4. CLICKS cover every interaction your screen claims (tabs, sheets, dialogs, kebabs, filters,
   sort, inline rename, expanders, dropzones, busy buttons) using `check` JS expressions that
   prove state changed (see `screens/codereview_list.py`). `expect` text alone is not proof.
5. Look at the screenshots the harness writes (`<Stem>.png`, `<Stem>Phone.png`) and fix what
   looks wrong before reporting: clipped text, misaligned rows, dead space, low contrast.
6. Report: files written, the gen.py `SCREENS` line to add, harness PASS lines for desktop and
   phone, and a list of any inventory item you could not represent (with the reason).
